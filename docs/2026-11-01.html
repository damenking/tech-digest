Anthropic VS Code Extension on Cursor Backdoored for Nearly 12 Hours
Attackers managed to compromise Anthropic's verified publisher account on the Cursor marketplace and injected malicious code into the Anthropic VS Code extension, leaving it backdoored for nearly 12 hours before it was detected and pulled. The method of initial access remains unknown, which is arguably the most alarming part — if the attacker bypassed Cursor's account verification, that raises questions about the integrity of the entire extension ecosystem. This is particularly sensitive because developer tools like Cursor are being used to write production code, meaning a compromised extension has a direct pipeline to anything an engineer is building. The extension almost certainly had access to API keys, file contents, and potentially tokens passed through the editor. Anthropic has not yet disclosed how many users were affected or what data may have been exfiltrated. The incident underscores a structural risk with AI coding assistants: they require deep integration with your development environment, and that attack surface is now a high-value target. Security researchers have been warning for months that the rush to ship AI-native developer tooling has outpaced security review processes. This is a good moment to audit what extensions you have installed, verify their permissions, and think about whether your editor has access to credentials it shouldn't. If you use Cursor with the Anthropic extension, assume your API keys and any secrets visible in your editor during that 12-hour window should be rotated.

How Researchers Took Over ChatGPT Accounts via HTML Preview Exploit
Parameter Labs published a detailed writeup explaining how they discovered and exploited a vulnerability in ChatGPT's HTML preview feature — the sandboxed iframe environment OpenAI uses to render interactive HTML apps inside chats. The exploit allowed them to exfiltrate session tokens and take over ChatGPT accounts, essentially turning the canvas/preview feature into an attack vector. The technique involves crafting a malicious HTML payload that, when rendered in the ChatGPT interface, can reach out to attacker-controlled infrastructure with the victim's authentication context. This is a classic case of a useful feature — interactive code previews are genuinely valuable — expanding the attack surface in ways that weren't fully accounted for. OpenAI has since patched the issue, but the writeup is worth reading if you ship web apps with sandboxed iframe rendering, as the lessons generalize. The incident also rhymes with a broader pattern: AI platforms are rapidly adding rich interactive features to stay competitive, and each new surface (artifacts, canvases, code interpreters) introduces fresh injection and exfiltration risks. Simon Willison also flagged this on his blog, noting it connects to ongoing concerns about prompt injection in agentic systems. The fact that this was found and disclosed responsibly is good — but it should prompt every AI platform shipping similar features to do a thorough security review of their sandboxing assumptions.

New 'Volta-Autodoxer' Malware Uses AI to Automatically Profile Victims
Security researchers have uncovered a new infostealer malware called Volta-Autodoxer that goes well beyond traditional credential theft — it uses AI tools to automatically aggregate and cross-reference stolen data to build detailed profiles of victims. Once it gets access to a machine, it collects login credentials, credit card numbers, Discord session tokens, and even mundane things like UberEats receipts, then feeds all of that into an AI pipeline that synthesizes a comprehensive dossier. This 'autodoxing' capability dramatically lowers the barrier for targeted attacks: rather than requiring a human analyst to piece together stolen fragments, the malware does the enrichment automatically and at scale. The practical implication is that even data that seems low-value in isolation — a food delivery receipt, a calendar invite — becomes weaponizable when combined with other stolen context. This is a meaningful evolution in the threat landscape, and it mirrors how defenders have been using AI for threat intelligence. The malware's discovery is a reminder that the same models being used to summarize documents and write code can be trivially repurposed for offensive operations. Organizations should be thinking about this not just as an endpoint security problem but as a data minimization problem: the less personal data that can be exfiltrated, the less useful the AI enrichment step becomes. No attribution has been reported yet, and it's unclear how widely deployed Volta-Autodoxer currently is.

Memdoor: Team of Five Small Qwen Models Beats Fable 5 on LiveCodeBench Hard
An open-source project called Memdoor has demonstrated that an ensemble of five Qwen3.8-27B models working collaboratively can outperform Fable 5 — a leading frontier model — on the hard subset of LiveCodeBench, which tests competitive programming and algorithmic reasoning. This is a meaningful result for a few reasons. First, it shows that multi-agent ensemble approaches can punch above their weight class when the task has clear correctness criteria (like coding, where you can verify outputs). Second, Qwen3.8-27B is a relatively modest open-weight model, meaning this approach is reproducible and affordable for teams who can't afford frontier API costs. Third, it suggests that benchmark leaderboards that rank single models may increasingly miss the point — in production, people will compose systems, not deploy raw models. The tradeoff is latency and cost: running five models in parallel is more expensive than one, though potentially cheaper than frontier API calls at scale. The Memdoor approach uses a shared memory architecture that lets the agent team maintain context across their collaborative session, which is the novel engineering piece here. This feels like an early glimpse of how open-source AI practitioners will increasingly compete with closed frontier models — not by matching them head-to-head, but by building smarter scaffolding around smaller models.

TCP Use-After-Free Vulnerability CVE-2026-98432 Scores CVSS 9.8
A critical use-after-free vulnerability in the Linux kernel's IPv4 TCP implementation has been disclosed with a CVSS score of 9.8 — essentially as severe as it gets without being a hard 10. A use-after-free in the TCP stack means an attacker can potentially manipulate kernel memory after it's been freed, which in the TCP context could allow for remote code execution or privilege escalation without user interaction. The CVE affects a wide range of Linux kernel versions and has been generating significant discussion on Hacker News, where it's one of the highest-scored items this week. Patch status and specific affected versions are detailed in the linked writeup, and if you run Linux in production — which is most of the tech industry — you should be reviewing your kernel versions and patch schedules immediately. This class of vulnerability is particularly nasty because TCP is fundamental infrastructure: essentially everything that communicates over a network touches it. Cloud providers, hosting companies, and anyone with exposed Linux hosts should treat this as urgent. The fact that it scored so high on the CVSS scale suggests the researchers who found it identified a reliable exploitation path, not just a theoretical issue.

Climate Models Have a Dangerous Blind Spot: Feedback Loops That Are Fueling Further Warming
A sobering MIT Technology Review piece digs into a growing concern among climate scientists: the feedback loops that cause warming to beget more warming are not adequately represented in the models we use for policy-making and emissions targets. As global temperatures rise, they trigger secondary effects — permafrost thawing releasing methane, reduced ice cover decreasing planetary albedo, forests dying and becoming carbon sources rather than sinks — that themselves drive further warming. Scientists have known about these mechanisms for years, but a growing body of research suggests we've been systematically underweighting them in our quantitative models. The practical consequence is that our current emissions reduction targets may be less sufficient than we think, because they're calibrated to models that underestimate the self-reinforcing nature of warming. This isn't a fringe position: it's increasingly the mainstream scientific concern. For technologists, this has implications for carbon accounting, for how we evaluate the climate impact of AI infrastructure (which is itself a significant and growing energy consumer), and for the urgency of electrification and efficiency work. The article doesn't offer easy solutions, but it's a useful corrective to any complacency that current climate commitments are adequate.

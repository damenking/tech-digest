Apple tightens macOS Full Disk Access controls to contain AI agent risks
Apple announced changes to how Full Disk Access (FDA) permissions work in macOS, specifically citing the rising threat posed by increasingly capable AI agents. The concern is real: agents like Meta's Muse, once granted FDA, can read messages, mail, browsing history, and essentially any file on your machine. Apple is adding new controls that will restrict what agents can do with that broad access. Meta reportedly argued that FDA is necessary for Muse to function well, but Apple disagreed and decided the security risk outweighs the convenience. This is a significant policy move because it signals that Apple is treating AI agents as a distinct threat category, not just another class of app. For developers building agentic software on macOS, this will likely require rethinking how their tools request and use permissions. The underlying security concern is well-founded — cryptographer Matthew Green and others have been warning that agents operating across shared environments can act as vectors for worm-like attacks, passing malicious instructions through shared caches or inter-agent communication. Apple's intervention is one of the first major platform-level responses to agentic AI security risks. It won't be the last, and it sets a precedent that other OS vendors will probably follow. If you're building or deploying AI agents on macOS, you should read Apple's developer guidance carefully — your current permission assumptions may break.

The author draws on their experience watching AlphaGo's famous Move 37 in Seoul in 2016 to illustrate that surprising AI outputs don't necessarily indicate genuine understanding or intentionality. This is a well-worn debate, but it's getting fresh urgency as the White House officially rebrands AI as 'super intelligence' and as AI agents are deployed in increasingly consequential contexts. The article's core point is that the impressive surface-level outputs of LLMs can mask fundamental brittleness — the model is doing sophisticated pattern matching over training data, not building and testing mental models of the world. For engineers, this isn't shocking news, but it's a useful reminder when evaluating whether to trust an agent's 'reasoning' in a production system. The danger isn't that LLMs are stupid — they're clearly very capable — it's that they can fail in ways that look nothing like how a human expert would fail, and those failure modes are hard to predict. The article's timing is relevant: as GPT-6 and Gemini 4 push capability envelopes, the temptation to anthropomorphize and over-trust these systems grows. Calibrated skepticism remains a professional virtue.

AI finally beat the best Stratego player in history, on a budget
Researchers have built an AI system that defeated the best human Stratego player in history, which is a more interesting achievement than it might sound. Stratego is a board game with hidden information — you don't know your opponent's piece identities until contact is made — which makes it fundamentally different from chess or Go and much harder for classical game-tree search approaches. The previous limits of AI in Stratego were directly tied to this hidden information problem; the game has an enormous imperfect-information game tree. The system that solved it apparently did so on a relatively modest budget, making it notable both for the capability achievement and the efficiency. Hidden information games are a useful proxy for real-world decision-making, where you rarely have complete knowledge of the state of the world. AI systems that can handle this class of problem well have implications for applications in cybersecurity (adversarial reasoning under uncertainty), business strategy, and negotiation. Stratego joining chess, Go, poker, and StarCraft on the list of games where AI has surpassed top humans closes another chapter in the benchmark-game tradition. It also highlights how the research frontier has moved: the interesting problems now involve real-world messiness like partial observability, not perfect-information games.

Cloudflare launches OHTTP gateway for privacy-preserving HTTP requests
Cloudflare announced an Oblivious HTTP (OHTTP) gateway service, which allows clients to make HTTP requests through an intermediary relay in a way that prevents the server from learning the client's IP address and prevents the relay from seeing the request content. OHTTP is an IETF standard that's been gaining traction as a privacy-preserving alternative to standard proxies, particularly for use cases like DNS-over-HTTPS, telemetry collection, and API calls where the client's identity shouldn't be linkable to the content of the request. Cloudflare's entry makes OHTTP much more accessible — previously, implementing OHTTP required running your own relay infrastructure or relying on small providers. For developers building privacy-sensitive applications — whether in health, finance, or just wanting to avoid logging user IPs — this is a practical tool worth evaluating. The Hacker News score (70) was modest, suggesting the audience was aware but not overwhelmed, which is appropriate for infrastructure tooling. OHTTP is most relevant in contexts where you're collecting telemetry or analytics and want to avoid the privacy liability of correlating data with user identities. Apple has been using a variant of this approach for its Private Relay and some Siri request handling. Cloudflare offering it as a managed service lowers the implementation barrier substantially.
